# Imported instance matrix preparation

`XRayInstancePreparation` prepares versioned, owned matrix data for `XRayLevelInstancedRenderer`. New batches retain the existing constructor-array alias until explicit preparation. Preparation copies the source array once, records its SHA256 input signature and writes the completed version last. Imported facts and the format version belong to the importer, not GameConfig.

For a prepared set, the renderer can reuse current/previous matrix payload for a batch whose matrix storage has never been exposed. `GetMatrix` returns a value for read-only consumers. The existing mutable `Matrices` getter permanently selects the full history-update path for that batch until explicit repreparation or deserialization. This preserves callers that mutate a previously obtained array, including mutations between cameras in the same Unity frame. Repreparation replaces owned storage and increments the history revision. Unprepared and unknown versions use the full path.

History remains before culling. Camera/shadow candidates, material resolution, 511-instance submission slices, reflection rendering, LOD payload, wind expansion and motion-vector mode are unchanged. No simulation objects, colliders, triggers or network state are toggled. No camera is needed for data ownership or preparation; rendering simply has no camera callbacks on a graphics-free server. Mirror itself is not installed or integration-tested by this change.

New geometry is prepared before saving its batch asset. Successful importer completion also updates prefab/scene dependencies, so resources-only early exits and drag-and-drop imports reach the same preparation process. Asset import/move callbacks, the post-reload repair pass and the build preprocessor repair missing/stale versions without rebuilding geometry or anomalies. The input signature includes version, location, cell size, batch order/names/counts and every matrix bit. Materials, wind and payload are read by the existing runtime path and are not cached by this optimization. An unchanged pass does not dirty or save the asset. The postprocessor queues bounded imported paths and guards its own save/import recursion.

This stage removes repeated CPU matrix preparation. It does not add spatial occlusion, reduce shadow submissions, unload objects or stream resources. Ordinary MeshRenderers continue using Unity culling. Baked renderer occlusion and custom instanced submissions require separate supported integration.

Future memory streaming must give each visual location/chunk explicit ownership of its batch set, meshes, materials and textures, release all owning references on unload, prefetch ahead of relevant views, use different entry/exit distances, and obey loading-time and resident-memory budgets. Simulation regions and client relevance must have separate ownership so host and dedicated-server state survive outside any local view. No unused streaming framework is introduced here.
