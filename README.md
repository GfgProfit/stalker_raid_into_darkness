## О проекте

**«Рейд во Мрак» (РВМ)** — независимый проект по переносу одноимённой модифицированной сборки на базе **S.T.A.L.K.E.R.: Anomaly / X-Ray Monolith** в **Unity 6 с High Definition Render Pipeline**.

Задача — не просто перенести геометрию локаций и заменить графику. Проект постепенно воссоздаёт игровые механики, поведение систем, обработку ресурсов и атмосферу оригинальной сборки на новой технической основе.

Это **не запуск X-Ray внутри Unity**. Игровые системы разрабатываются на C#, визуальная часть — с использованием HDRP, HLSL и инструментов Unity. Для переноса контента создаётся собственный слой совместимости с форматами и источниками X-Ray.

### Основные ориентиры

- **Сохранение узнаваемого геймплея:** механики и взаимодействия должны оставаться близкими к исходной сборке.
- **Совместимость с ресурсами X-Ray:** модели, анимации, материалы и локации проходят через собственные инструменты импорта.
- **Разделение систем:** игровая логика, данные, представление и редакторские инструменты развиваются независимо там, где это практически оправдано.
- **Измеримая производительность:** изменения проверяются регрессионными тестами и воспроизводимыми бенчмарками.
- **Основа для будущего развития:** кооператив, инструменты моддинга и SDK запланированы после завершения основных этапов переноса.

## Как устроен репозиторий

```text
Assets/
├── _Source/
│   ├── Anomalies/          # Аномалии и их ресурсы
│   ├── Items/              # Оружие, снаряжение, определения предметов
│   ├── Levels/             # Импортированные локации
│   ├── Scripts/            # Игровая логика и интеграции
│   └── Shaders/            # Шейдеры и графические эффекты
├── _Modules/
│   └── Inventory/          # Независимый модуль инвентаря
├── _Tools/
│   └── X-Ray OGF OMG Importer/  # Инструменты импорта X-Ray
└── _BENCHMARK/              # Бенчмарки, сценарии, проверки

Packages/                   # Зависимости Unity Package Manager
ProjectSettings/            # Настройки проекта Unity
```

Игровой код и интеграции находятся преимущественно в `Assets/_Source/Scripts`. Инструменты переноса ресурсов и вспомогательные модули вынесены отдельно, чтобы ими было проще управлять и тестировать.

## Как открыть проект

> [!CAUTION]
> Инструкции ниже предназначены **для разработчиков, имеющих доступ к репозиторию и необходимым исходным ресурсам**. Это не инструкция по установке готовой игры.

**1. Установите инструменты**

- **Unity Hub** и редактор **Unity 6000.6.7f1**.
- **Git** и **Git LFS**.
- При работе с переносом ресурсов — собственную подготовленную копию исходных данных Anomaly и, при необходимости, установленный **Mod Organizer 2**.

**2. Клонируйте проект**

```bash
git lfs install
git clone https://github.com/GfgProfit/stalker_raid_into_darkness.git
cd stalker_raid_into_darkness
git lfs pull
```

**3. Откройте папку в Unity Hub**

Выберите **Add project from disk** и укажите каталог репозитория. Дождитесь импорта пакетов и ассетов. Версия редактора зафиксирована в `ProjectSettings/ProjectVersion.txt`.

**4. Настройте источники X-Ray при необходимости**

Откройте **Tools → X-Ray → Asset Sources**. Укажите папку распакованных ресурсов Anomaly, корень MO2 и нужный профиль. Система разрешения ресурсов учитывает порядок модов; подробности описаны в документации импортёра.

**5. Работайте с нужной сценой или инструментом**

Набор сцен, источников и готовность игровых систем зависят от текущего этапа разработки. **Клонирование репозитория само по себе не гарантирует готовую к запуску игровую сборку.**

## Планы развития

| Этап | Направление | Статус |
| :-- | :-- | :-- |
| 01 | Основа Unity HDRP, инструменты импорта и базовые игровые системы | **Реализовано частично / развивается** |
| 02 | Полный перенос локаций, ресурсов, аномалий и поведения сборки | **В работе** |
| 03 | Доработка AI, навигации, анимаций, физики и интеграции систем | **В планах / частично в работе** |
| 04 | Профилирование, устранение узких мест и стабилизация | **Постоянная работа** |
| 05 | Кооперативный режим на базе **Mirror** | **Запланировано** |
| 06 | **SDK и моддинг:** конфигурации, скрипты, инструменты создания дополнений | **Запланировано** |
| 07 | Собственный лаунчер и управление пользовательскими дополнениями | **Запланировано** |

Порядок и объём этапов могут меняться по мере развития проекта. Наличие технологии в планах не означает, что она уже интегрирована.
