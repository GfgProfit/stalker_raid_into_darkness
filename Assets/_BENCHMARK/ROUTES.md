# Маршруты Release

Канонические профили — `Scenarios/Military_Overview.asset` и `Scenarios/Military_PlayerEye.asset`, оба типа BenchmarkScenario. ID запуска: `military-overview` и `military-player-eye`. Старый `Scenarios/l07_military.route.json` сохранён как исторический эталон Overview. Привязка к сцене использует GUID, а путь служит метаданными; смена карты не подставляет чужие координаты. Проверенных Player Eye поз Escape в этой задаче нет.

Пользовательские точки находятся в `Authoring/l07_military_player_eye.prefab`. В сцене Military контейнера и benchmark-компонентов нет. Prefab сохраняет world position/rotation точек; runtime получает только записанные значения профиля, без поиска имён и без наследования масштаба. При повторном импорте локации профиль модуля не перезаписывается.

## Обновление точек

1. Откройте `Tools/RVM/Benchmark`, выберите **Military — Player Eye** в Release route.
2. Нажмите **Открыть authoring-prefab**, измените Pos 1–4 и сохраните prefab.
3. Выделите корень prefab и нажмите **Обновить маршрут из выбранного корня Pos 1–4**. Данные читаются в мировых координатах и проверяются по ключам; высота глаз не добавляется.
4. Нажмите **Собрать Release с маршрутами текущей сцены**. Уже собранный Player хранит прежний снимок и требует пересборки после обновления профиля.

Обновить можно и четыре явно выбранные ссылки в существующих полях POS через кнопку подключения: для route-профиля она сохраняет данные, не добавляет runner в сцену. Overview не меняется при обновлении Player Eye. Камера профиля хранится отдельно от поз и не заменяется настройками случайно выбранного Transform.

Для другой карты создайте Transform-only prefab с Pos 1–4 внутри модуля. В обычной сцене карты укажите рабочую камеру в UI, выберите prefab в Project и используйте **Создать маршрут из выбранного module-prefab для текущей сцены**. Сохраните asset внутри `_BENCHMARK`, настройте фиксированную погоду и часы в UI. Для профиля без проверенных точек запуск не создаётся. Новая карта не требует изменения runner.

## Запуск

Сборка сохраняет Player отдельно от папки Launchers под Archive. UI открывает launchers последней сборки. Имена `<profile>_U.cmd` и `<profile>_G1.cmd` выбирают профиль и состояние. `Fixed_Series.cmd` запускает Overview U1 → G1_1 → G1_2 → U2, затем Player Eye в том же порядке; первая невалидная попытка останавливает серию. Результаты получают новые каталоги, существующие не перезаписываются. Python должен быть доступен в PATH, как в текущей рабочей среде.

Закройте Editors и workers перед Player: launcher проверяет их отсутствие и не завершает пользовательские приложения. Фокус устанавливается один раз при появлении окна, затем не возвращается принудительно. Основная серия не включает callback observer и captures. `--kind capture` — отдельный технический запуск, не дополнительная основная попытка.

В поставке LocationBatching05 `Ordinary_Game.cmd` открывает отдельный обычный Release, собранный при физическом отсутствии модуля. Общий генератор также предоставляет запуск benchmark Player без экспериментальных аргументов: тогда route controller выключен и production defaults не меняются. Это разные проверки, их нельзя выдавать друг за друга.

Production `GameConfig.asset` остаётся неизменным с группировкой off. U/G1 меняют только временную копию конфигурации renderer. Завершение и Abort освобождают эту копию, восстанавливают камеру, погоду и pacing. Повторный teardown идемпотентен и не проверяет заново уже возобновившееся игровое время. Симуляция, коллайдеры, аномалии, authority и жизненный цикл игровых объектов не управляются маршрутом.
