# Independent benchmark module

All campaign runtime, Editor tooling, scenarios, experimental routes, assets and registrations are owned by `Assets/_BENCHMARK` and its sibling `.meta`. Dependencies point from these assemblies to game assemblies. Ordinary scenes contain no benchmark components.

Player Eye authoring lives in `Authoring/l07_military_player_eye.prefab`. The original `PLAYER_EYE_BENCHMARK_POSES` container was copied and its world poses verified before removal from Military. No authoring objects remain in ordinary scenes. `Scenarios/Military_Overview.asset` and `Scenarios/Military_PlayerEye.asset` extend the existing BenchmarkScenario format. Their scene and authoring GUIDs are strings; the authoring prefab is not a runtime asset dependency. Build copies receive one disabled route controller and the matching scene profiles only for the module's explicit Release build. Ordinary builds receive neither component nor profile references from their source scene.

`-benchmark-route <profile ID>` requires a matching stable scene GUID. There is no coordinate fallback for another map. `-location-batching U|G1` uses private transient GameConfig copies; it does not save the production configuration. The technical observer is installed only with `-batching-counters`. All these entry points, launchers, profile tests and Editor preferences disappear with the module. The only additional preference is `Rvm.Benchmark.ReleaseDirectory`; no project setting, Resources registration or production assembly reference was added. See `ROUTES.md` for editing and launcher instructions.

`AllocationCounterControl` validates the managed allocation counter used by the local History harness. `ShadowOnlyFeasibilityBenchmark` owns the rejected shadow-only prototype, source observations, local costs and fallback evidence. Both are removed with this module; neither adds production hooks. Measurement scope and invalid-counter handling are defined in `MEASUREMENTS.md`.

`BenchmarkNativeSubmissionState`, the `-instance-native-submission A|B` entry point, launcher option and native technical counters also belong exclusively to this module. They consume the production renderer's general session override and published statistics, save no GameConfig assets and restore each prior nullable override on completion/Abort/exit. Current B requests BRG Camera color and Light shadows owned by the prepared Game camera. Successful native preparation skips the complete legacy instance loop; unsupported contracts retain the original fallback. Zero legacy calls describes that API only, while native shadow counts describe repeated source/submesh commands and instance references per Light view, not GPU draws. Reflection coverage requires actual view and command evidence. Production GameConfig enables native submission by default and keeps grouping disabled; removing this module preserves these defaults. The production renderer, physical/index bounds, wind-bound caches, required shader-build setup and functional HDRP owner-camera scope remain independent of this module. Removing the module removes the experimental controller, evidence writer and tests, without requiring any scene cleanup.

`BenchmarkNativeCullingObserver` is installed only by the separate technical observer. Its reflection-based forwarding delegate, elapsed samples, availability/restoration evidence and tests are removed with the module; no production culling callback depends on it. It preserves original callback arguments, return values and exceptions and restores the installed delegate before releasing session overrides. Game preparation, Reflection preparation and native Camera/Light/reflection culling elapsed sums retain separate callback populations before normalization; context callbacks, downstream native work and GPU execution are excluded. The Unity.Collections reference added to Rvm.Benchmark.Runtime uses the existing package and does not introduce an Entities dependency.

The four historical poses are stored in `Scenarios/l07_military.route.json`; the verified Transform-only `BENCHMARK_POSITION` hierarchy was removed from the ordinary scene after checking external references. The route builder injects its controller only into build copies. Legacy persistent runner integration is restricted to scenes inside this module, so it cannot reintroduce mandatory components into ordinary locations. `Rvm.Benchmark.Last` is an optional EditorPrefs report pointer; pending route/session keys use the `Rvm.Benchmark` prefix and can be erased when permanently removing the module.

`CleanReleaseRoute07` and Visual08/09/Light10/Shadow11 now reside here. Gameplay hooks have been retired. Requesting historical visual modes or the low-level event journal fails explicitly rather than producing an incomplete old-format experiment. Historical results and the original package diagnostics payload remain available in Git and Archive. Particle inspection is a module-owned, separately enabled observer; it does not instrument the particle loop.

`LocationPreparationBenchmark` selects the production full-history fallback with `-location-preparation A`, or prepared matrices with `-location-preparation B`. It changes the loaded data version through reflection; the game exposes no benchmark toggle. Use the same route Player and `-clean-route-output` for both. `-location-preparation-work -preparation-output <Archive directory>` runs separate warmed CPU measurements. `-preparation-counters` and `-preparation-capture` are separate technical runs and must not be treated as timing baselines.

The functional HDRP 17.6 shadow binding fix lives in `Assets/_Tools/X-Ray OGF OMG Importer/Editor/Rendering`. Its payload contains the resolver, functional call-site changes and the versioned Game-camera ownership scope used by native shadow culling. That scope is a production contract rather than a benchmark observer; removing `_BENCHMARK` must retain it. The payload installs no request observer, event journal or diagnostic callback. Runtime frame pacing lives in `Assets/_Source/Scripts/Utils/RuntimeFramePacing.cs`. Finite particle frame caching and MatrixHistory remain production code, with regression tests outside the module.


`ReleaseCpuDiagnosticSession` and `-benchmark-cpu-diagnostic` remain entirely in this module. They own Release recorder inventory, optional Archive marker selection, bounded OS thread CPU samples, clock anchors and recorder/thread-handle disposal. CPU/PIX/FTM modes cannot be combined. The ordinary game has no dependency on this collector, its configuration or its output files; removing the module removes the complete diagnostic mode.
## Reversible removal

The Frame Timing Manager diagnostic also belongs entirely to this module: `FrameTimingDiagnosticSession`, its route/build integration, `BENCHMARK_FRAME_TIMING_DIAGNOSTIC`, `-benchmark-frame-timing-diagnostic`, policy checks and regression tests. It adds no production scene component, game assembly dependency, global define or package. Its two native clock functions use the existing Windows system DLL; no plugin is installed. Buffers belong to the session and are released during completion/Abort restoration. Remove these sources and metas with `_BENCHMARK`, clear the optional build environment variable and rebuild the ordinary Player with Frame Timing Stats restored to the intended project setting. Existing diagnostic binaries retain their instrumentation until rebuilt or removed. Retain Archive CSV, clock brackets, reports and the task-owned external driver as investigation evidence; they are not game dependencies.

PIX diagnostics add only module-owned `PixDiagnosticPolicy`, `PixDiagnosticSession`, `Native/RenderCostPixBridge.cpp`, its build script/documentation, `Plugins/x86_64/RenderCostPixBridge.dll`, the official MIT `WinPixEventRuntime.dll`, plugin import settings, regression tests and `Launchers/run_pix_diagnostic.py`. Neither plugin is preloaded. Ordinary startup never calls the bridge; no game assembly, production scene, package registration or global scripting define refers to it. Remove these with `_BENCHMARK` and its metas. Archive captures, the separately retained diagnostic Player and external PIX installation/portable tooling are independent evidence/tools, not production requirements. Removing the module requires rebuilding a delivered Player; deleting source assets does not remove DLLs from an already built diagnostic Player.

1. Preserve unsaved scenes and close every Editor for Production. Do not remove the module while Unity is importing it.
2. Move `Assets/_BENCHMARK` and `Assets/_BENCHMARK.meta` together outside Assets into a task-owned Archive directory. Keep every `.meta` and GUID. No project-wide compile symbol or package registration is required by this module; `CLEAN_RELEASE_ROUTE07` is scoped to the route build's extra defines.
3. Open Production, wait for Runtime and Editor compilation, and check ordinary scenes/prefabs for missing scripts and dependencies. Inspect assembly references and the actual loaded assemblies, not names alone. Run production regression tests.
4. Build and run an ordinary non-Development Player without route-specific defines or build processors. Verify the functional HDRP resolver is present and the request diagnostics type is absent. Inspect build output and runtime errors.
5. Restore the directory and sibling `.meta` together while the Editor is closed when measurements are still needed. For final removal leave them excluded, delete no Git history or Archive evidence, and rebuild the delivered Player.

A source inventory and the scene-detachment evidence are stored in the same task directory. That historical build does not validate later native submission changes; recheck physical removal, current source inventory, production tests and an ordinary Release build for the current implementation.

`LocationBatchingBenchmark` owns A/B initialization, the optional CPU callback wrapper and technical captures. Production submission plans and their regression/visual tests remain outside this module. Removing the module leaves normal imports, migration, culling, shadows and runtime submission grouping operational.

The punctual shadow distance comparison belongs entirely to this module: `PunctualShadowDistanceTrial`, its optional technical HDRP inventory, CleanReleaseRoute07 integration, launcher flags and test fixtures are removed together. It is created only for an explicit `-punctual-shadow-mode A|B` route session; no production scene target or ordinary startup component refers to it. The trial restores each original per-light HDRP state before other session state is released. Deleting the module removes this experiment and its command-line handling; it does not remove ordinary lights or change the shared production configuration.

The coded punctual-shadow mode C has been retired from current source. No periodic distance loop, manual fade factor or shadow-dimmer writer remains in the module. Historical C sources, Players and results remain in Archive; their removal from current source does not authorize deleting that evidence.
