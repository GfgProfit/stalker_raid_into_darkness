# Independent benchmark module

All campaign runtime, Editor tooling, scenarios, experimental routes, assets and registrations are owned by `Assets/_BENCHMARK` and its sibling `.meta`. Dependencies point from these assemblies to game assemblies. Ordinary scenes contain no benchmark components.

Player Eye authoring lives in `Authoring/l07_military_player_eye.prefab`. The original `PLAYER_EYE_BENCHMARK_POSES` container was copied and its world poses verified before removal from Military. No authoring objects remain in ordinary scenes. `Scenarios/Military_Overview.asset` and `Scenarios/Military_PlayerEye.asset` extend the existing BenchmarkScenario format. Their scene and authoring GUIDs are strings; the authoring prefab is not a runtime asset dependency. Build copies receive one disabled route controller and the matching scene profiles only for the module's explicit Release build. Ordinary builds receive neither component nor profile references from their source scene.

`-benchmark-route <profile ID>` requires a matching stable scene GUID. There is no coordinate fallback for another map. `-location-batching U|G1` uses private transient GameConfig copies; it does not save the production configuration. The technical observer is installed only with `-batching-counters`. All these entry points, launchers, profile tests and Editor preferences disappear with the module. The only additional preference is `Rvm.Benchmark.ReleaseDirectory`; no project setting, Resources registration or production assembly reference was added. See `ROUTES.md` for editing and launcher instructions.

`AllocationCounterControl` validates the managed allocation counter used by the local History harness. `ShadowOnlyFeasibilityBenchmark` owns the rejected shadow-only prototype, source observations, local costs and fallback evidence. Both are removed with this module; neither adds production hooks. Measurement scope and invalid-counter handling are defined in `MEASUREMENTS.md`.

The four historical poses are stored in `Scenarios/l07_military.route.json`; the verified Transform-only `BENCHMARK_POSITION` hierarchy was removed from the ordinary scene after checking external references. The route builder injects its controller only into build copies. Legacy persistent runner integration is restricted to scenes inside this module, so it cannot reintroduce mandatory components into ordinary locations. `Rvm.Benchmark.Last` is an optional EditorPrefs report pointer; pending route/session keys use the `Rvm.Benchmark` prefix and can be erased when permanently removing the module.

`CleanReleaseRoute07` and Visual08/09/Light10/Shadow11 now reside here. Gameplay hooks have been retired. Requesting historical visual modes or the low-level event journal fails explicitly rather than producing an incomplete old-format experiment. Historical results and the original package diagnostics payload remain available in Git and Archive. Particle inspection is a module-owned, separately enabled observer; it does not instrument the particle loop.

`LocationPreparationBenchmark` selects the production full-history fallback with `-location-preparation A`, or prepared matrices with `-location-preparation B`. It changes the loaded data version through reflection; the game exposes no benchmark toggle. Use the same route Player and `-clean-route-output` for both. `-location-preparation-work -preparation-output <Archive directory>` runs separate warmed CPU measurements. `-preparation-counters` and `-preparation-capture` are separate technical runs and must not be treated as timing baselines.

The functional HDRP 17.6 shadow binding fix lives in `Assets/_Tools/X-Ray OGF OMG Importer/Editor/Rendering`. Its payload contains only the resolver and functional call-site changes. It installs no request observer, event journal or diagnostic callback. Runtime frame pacing lives in `Assets/_Source/Scripts/Utils/RuntimeFramePacing.cs`. Finite particle frame caching and MatrixHistory remain production code, with regression tests outside the module.

## Reversible removal

PIX diagnostics add only module-owned `PixDiagnosticPolicy`, `PixDiagnosticSession`, `Native/RenderCostPixBridge.cpp`, its build script/documentation, `Plugins/x86_64/RenderCostPixBridge.dll`, the official MIT `WinPixEventRuntime.dll`, plugin import settings, regression tests and `Launchers/run_pix_diagnostic.py`. Neither plugin is preloaded. Ordinary startup never calls the bridge; no game assembly, production scene, package registration or global scripting define refers to it. Remove these with `_BENCHMARK` and its metas. Archive captures, the separately retained diagnostic Player and external PIX installation/portable tooling are independent evidence/tools, not production requirements. Removing the module requires rebuilding a delivered Player; deleting source assets does not remove DLLs from an already built diagnostic Player.

1. Preserve unsaved scenes and close every Editor for Production. Do not remove the module while Unity is importing it.
2. Move `Assets/_BENCHMARK` and `Assets/_BENCHMARK.meta` together outside Assets into a task-owned Archive directory. Keep every `.meta` and GUID. No project-wide compile symbol or package registration is required by this module; `CLEAN_RELEASE_ROUTE07` is scoped to the route build's extra defines.
3. Open Production, wait for Runtime and Editor compilation, and check ordinary scenes/prefabs for missing scripts and dependencies. Inspect assembly references and the actual loaded assemblies, not names alone. Run production regression tests.
4. Build and run an ordinary non-Development Player without route-specific defines or build processors. Verify the functional HDRP resolver is present and the request diagnostics type is absent. Inspect build output and runtime errors.
5. Restore the directory and sibling `.meta` together while the Editor is closed when measurements are still needed. For final removal leave them excluded, delete no Git history or Archive evidence, and rebuild the delivered Player.
